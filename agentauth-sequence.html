01 — User Consent
The user defines what the agent can do
"Buy me a flight under $500." AgentAuth captures this intent as a cryptographically signed consent — scoped by amount, merchant, time, and action.
POST /v1/consents

{ "intent": "Buy flight NYC",
  "max_amount": 500,
  "currency": "USD",
  "expires_in": 86400 }
02 — Token Minting
A Biscuit token is minted
Cryptographic bearer credential with embedded constraints. Biscuit tokens support capability attenuation — permissions can only decrease through delegation chains. ED25519 signed.
// delegation_token
{ "token": "bsc_eyJ...",
  "type": "biscuit_v2",
  "signing": "ed25519",
  "attenuable": true,
  "scope": "purchase ≤ $500" }
03 — Delegation Chain
Permissions attenuate at each hop
Agent A delegates to Agent B. At each hop, the token's scope mathematically shrinks. $500 → $347. A payment agent can never exceed the original spending limit.
POST /v1/authorize

{ "action": "purchase",
  "amount": 347,
  "merchant_id": "merch_united" }

→ { "decision": "ALLOW", "latency": "0.4ms" }
04 — Merchant Verification
Cryptographic proof on file
Merchant verifies offline in under 1ms. Zero network round-trips. The receipt is court-admissible evidence. Chargebacks become mathematically impossible.
POST /v1/verify

{ "auth_code": "auth_7k9..." }

→ { "valid": true,
    "receipt": "rcp_x8m..." }
